# Library management system

Omowunmi Olawehinmi · Student ID 301910155


This repository documents a fictional Library management system designed to explore modern database concepts across relational modelling, SQL optimisation, transaction behaviour, NoSQL event storage, and distributed database design. The work is organised as a portfolio of practical exercises, each with supporting SQL scripts, explanations, screenshots, and evidence.

## Project overview

The case study models a library in which:

- librarians manage a catalog of lendable book copies;
- members register with unique contact details;
- loans are created when a book copy is checked out;
- returns are recorded and overdue loans can be identified;
- system behaviour is evaluated using relational constraints, transactions, query plans, and document-based event data.

The design keeps core data in PostgreSQL and uses MongoDB for event-document modelling in the NoSQL portfolio. This combination demonstrates how different database technologies are suited to different problems, while still representing the same business scenario.

## What each portfolio covers

- Portfolio 1: relational design, entity relationships, normalisation, schema creation, data validation, and constraint testing.
- Portfolio 2: SQL queries, index comparison, performance measurement, and query-plan analysis.
- Portfolio 3: transaction isolation, commit and rollback behaviour, and concurrency with locking.
- Portfolio 4: MongoDB document modelling, event storage, query examples, and validation of data types and IDs.
- Portfolio 5: distributed database and cloud design considerations, including replication, consistency, sharding, and recovery trade-offs.

## Evidence and assessment

The repository brings together structured technical evidence from each exercise, including:

- schema and sample data SQL scripts;
- constraint and validation tests;
- example queries and execution plans;
- screenshots of results and comparisons;
- written explanations of design decisions and trade-offs.

This demonstrates both practical implementation and critical evaluation of database principles in a realistic case-study setting.
